# DEP-15/18 dependency-audit graph binding

Implemented 2026-11-09. **Bounded audit/report graph consistency implemented;
13 wrapper and 28 candidate regressions PASS.** Production signing, source-to-package execution
provenance and final deployment acceptance remain pending under
[the deployment plan](deployment-readiness.md).

The prior unsigned checker pinned an app audit's bytes but could not tell whether
the audit described the same source or restored graph as its toolchain report.
An audit from a different graph could satisfy its passing counters. This change
adds an observed binding at the existing audit wrapper and requires that binding
at the existing handoff checker. It does not introduce signing authority or a
replacement for trusted build attestations.

## Bound audit and toolchain inputs

```powershell
# Run after the candidate's matching locked target-specific AOT restore.
.\scripts\Invoke-CiDependencyAudit.ps1 -AppOnly -Architecture x64
.\scripts\Export-CiToolchain.ps1 -Architecture x64 -RequireAot
# Preserve the target's outputs before another architecture changes obj assets.
# Repeat with arm64 for the second target.
```

The audit always reads the fixed app `obj/project.assets.json`, not an arbitrary
caller-supplied snapshot. Reads are bounded to 16 MiB and strict UTF-8. The
parsed graph must identify the actual app project, exactly one original/current
Windows target framework and that framework's base/selected-RID targets. Missing,
foreign or mixed target graphs fail. The wrapper samples the full nonzero Git
HEAD and exact assets SHA-256 before and after the no-restore NuGet command and
again before emitting the bound public summary. Changed HEAD or assets reject
the audit; raw reports remain in ignored private evidence.

The public passing summary retains the existing clean counters and adds:

```json
{
  "binding": {
    "source_commit": "<40 lowercase hex>",
    "architecture": "x64",
    "assets_sha256": "<64 lowercase hex>",
    "project_set": "app",
    "scope": "app_assets_observed_before_and_after_audit"
  }
}
```

No local paths, package findings or account values appear in this binding.
The matching toolchain export records `AssetsSha256` for its own stable parsed
assets bytes. Handoff compares source/target/scope/hash and records a bounded
`MATCH` for each architecture. Signing authorization remains false and nine
production/provenance gates remain pending, including authenticated execution.

## Compatibility and failures

Ordinary solution audits and `-AppOnly` without `-Architecture` retain their
unbound behavior for CI/development checks. They cannot satisfy a new unsigned
candidate handoff. Supplying an architecture without app-only scope fails.

Legacy toolchain exports lack `AssetsSha256`; legacy dependency summaries lack
`binding`. The stricter checker deliberately rejects both. Regenerate evidence
against the reviewed new candidate source/graph; never add invented bindings to
historical reports. Historical package/hash PASS records remain historical.

A stale public summary is removed before audit. Intermediate summaries stay
private until the final binding check succeeds, so a changed source/graph or
failed vulnerability audit cannot leave a new public `PASS`. Failures use fixed
diagnostics and retain the wrapper's nonzero exit. The candidate checker retains
its existing pinned-input mutation checks, privacy, alias protection and atomic
failure-report behavior.

## Verification and limits

```powershell
python -B -m unittest discover -s tests/scripts -p test_ci_dependency_binding.py
python -B -m unittest discover -s tests/scripts -p test_release_candidate.py
```

The isolated wrapper tests use actual files, PowerShell wrapper and Python
summary validation with a synthetic NuGet command. They cover exact x64/ARM64
bindings, graph/framework/project mismatch, missing/corrupt/oversized input,
invalid source/UTF-8, mid-audit assets/HEAD changes, stale-success removal, explicit
scope, legacy unbound app/solution audits and vulnerability failure. Candidate tests
exercise real synthetic MSIX and reject unbound/mismatched/private binding values.

Observed hashes bind the two local reports' declarations. They do not authenticate
Git history, establish a clean working tree, pin the advisory database, verify
which compiler executed, or prove that the supplied package was built from those
assets. The vulnerability command still audits only its known NuGet scope;
native/vendor advisory applicability and full linked-code SBOM closure retain
their separate requirements. No historical real package pair was regenerated by
this bounded follow-up. Hosted execution and final signed candidates need fresh
evidence.
